## 项目·架构

### P001 你负责的项目是什么？解决了什么问题？

我做的是影院售票与 AI 助手项目。交易侧用 MySQL、Redis Lua 和 RabbitMQ 处理抢座、幂等与超时取消；AI 侧用 LangGraph 和 MCP 查询真实业务，重点是交易一致性、权限边界和可评测的回答效果。

### P002 为什么选择影院售票作为项目场景？

影院售票包含选座竞争、订单状态机、超时释放和售后闭环，既能展示常规后端能力，也能验证并发一致性。加入只读 AI 查询后，还能体现模型与业务权限的边界设计。

### P003 整体架构是怎样的？

React 负责界面，Spring Boot 承担交易，MySQL 保存事实，Redis 做短期协调，RabbitMQ 处理超时取消。AI 网关管理身份和会话，LangGraph 编排查询，MCP 连接 Java，Chroma 只索引长期记忆。

### P004 为什么不是把所有代码都放在一个服务里？

交易侧采用 Java 模块化单体，让订单和座位共享数据库事务，减少分布式复杂度。AI 单独用 Python，是为了模型生态和独立迭代；代价是增加内部调用、鉴权和部署管理。

### P005 为什么 AI 不直接连 MySQL？

模型直连数据库难以控制 SQL、查询范围和订单归属。我用固定 Java 接口暴露只读能力，模型只传受约束的查询条件；参数化查询、权限和业务规则仍由 Java 执行。

### P006 为什么选 Spring Boot、MyBatis 和 JdbcTemplate？

Spring Boot 集成 Web、事务和中间件。部分账户、影院查询用 MyBatis，通用管理和部分订单 SQL 用 JdbcTemplate；按场景选择，统一保留参数绑定与服务层业务校验。

### P007 数据库主要有哪些实体？

核心有用户、影片、影院、影厅、座位、场次、订单、票项、支付和退款。订单描述一次购买，票项对应每个座位；支付退款独立记录，便于追踪生命周期。

### P008 影片状态和售票状态有什么区别？

上映中是影片阶段，已排期表示电影院确有场次，可购买还要满足未开场、销售窗口和影院状态。三者不能混用，查询还必须保留用户指定日期。

## 项目·交易一致性

### P009 Redis 锁座具体怎么保证原子性？

锁座用 Redis Lua 先检查本次所有座位键，有一个冲突就整体失败；全部可用才统一写持有人和五分钟 TTL。这样正常冲突不会留下半组锁，但最终下单仍由数据库复核。

### P010 为什么 Redis 锁之外还要查 MySQL？

Redis 只协调临时选座，可能过期或故障。下单时还锁定数据库座位行，核验有效订单和 Redis 持有人；MySQL 保存最终占座事实，不能仅凭拿到缓存锁就创建订单。

### P011 座位锁为什么要有持有人校验和 TTL？

持有人校验避免释放别人的锁，五分钟 TTL 处理关页面、断网等未主动解锁的情况。锁过期只是临时许可失效，已下单座位是否占用仍查 MySQL。

### P012 什么是幂等？项目里如何实现？

下单使用用户 ID 加 requestId 和唯一约束，重复请求返回同一订单；支付使用 paymentNo 防重复流水。幂等键必须绑定可信用户，不能全站只看一个请求号。

### P013 为什么总价必须由服务端计算？

前端价格能被修改，后端必须按数据库场次票价乘以已校验座位数重新计算，并将金额落库。前端负责展示，后端决定可信金额。

### P014 支付流程和状态机怎么设计？

支付先锁订单，检查归属、未过期和 UNPAID，再写唯一流水并完成 PAID 到 ISSUED 的订单、票项更新，同一事务提交。相同流水重试返回已有结果，冲突流水被拒绝。

### P015 这个项目接了什么支付渠道？

目前支付和退款都是模拟流程，没有接微信或支付宝，也没有真实资金划转。后续接入需补回调验签、金额核对、回调幂等、渠道退款和对账。

### P016 为什么一个订单既有订单状态，又有票项状态？

订单表示一次交易，票项表示每个座位的入场权益。整单退票更新两层状态，验票则精确到单张票；某张已验票会影响整单退票资格，两层职责不能简单合并。

### P017 退票规则为什么放数据库，不写死在代码里？

退票政策会调整，放数据库可由管理员维护，订单页面、AI 和退票接口读取同一当前策略。前端倒计时只是提示，最终资格仍由后端重新核验。

### P018 如何防止支付与超时取消同时发生？

支付和取消都锁同一订单行，串行检查状态与到期时间。支付只接受未过期 UNPAID，取消只改变到期 UNPAID；先成功的一方改变状态后，另一方不能做相反转换。

## 项目·异步消息

### P019 订单超时取消的消息链路是什么？

订单提交后发布延迟消息，经 TTL 和死信路由进入取消队列。消费者锁行并检查未支付且已过期，再取消并释放本人座位锁；手动 ACK，失败有限重试后进入失败队列。

### P020 为什么延迟消息不能直接取消订单？

消息可能晚到或重复，只是检查提醒。消费者必须读取数据库最新状态，仅取消到期且仍为 UNPAID 的订单；已经支付或取消就跳过，不能把消息内容当最终事实。

### P021 RabbitMQ 失败后怎么补偿？有没有事务消息？

订单消息目前是事务提交后发布，提交成功但发布失败仍有窗口，由每分钟扫描过期订单补偿。订单链路尚无 Outbox；长期记忆索引已有 Outbox，不能把两者混为一谈。

### P022 消息消费如何幂等？

消息用稳定 messageId，消费记录有唯一约束，重复消息直接跳过。消费记录与订单取消在同一数据库事务中，取消失败时一起回滚，后续重试仍能执行。

## 项目·AI与权限

### P023 为什么同时用 Dify 和内部 Agent？

Dify 负责通用聊天，内部 Agent 负责真实业务查询。两者入口、Redis 历史、生成锁、停止和反馈独立，共用网站身份校验，但不互传对话或长期记忆。

### P024 LangGraph 在这里做什么？流程有几步？

共享图有 prepare、clarify、simple、agent、tools、draft、reflect、respond 八类节点。代码选择简单查询或有界 ReAct 循环，之后检查任务、生成草稿并验证；普通和流式问答共用。

### P025 Agent 能调用哪些业务工具？

模型可查电影、场次、座位、本人订单、规则及推荐，另有 ask_user 追问。前四类走 MCP；退票资格由订单结果解释。模型不能锁座、下单、支付、退款或执行任意 SQL。

### P026 项目里接入 MCP 了吗？

已接入独立 MCP Server，通过官方 Python SDK 和 Streamable HTTP 提供电影、场次、座位、本人订单四类查询。MCP 再访问固定 Java 接口，业务权限与归属仍由 Java 决定。

### P027 RAG 是怎么做的？用的是什么向量库？

规则知识约按五百字符切片、重叠八十字符，先有界关键词召回，再可选云端 rerank，默认最多三十候选取四条。Chroma 和 BGE 用于长期记忆，不是规则知识的初始召回。

### P028 如何避免 AI 编造票务信息？

实时场次、订单和资格以 Java 查询为准，知识保留来源，记忆只补偏好。执行层检查日期、ID 来源及任务字段，草稿做规则校验或一次反思；不足时披露，不能保证永不出错。

### P029 如何保证 Agent 查询的是当前登录用户自己的订单？

Java 校验登录并发短期只读凭证，网关得到可信用户 ID；MCP 客户端在服务端传递身份，模型不能指定 userId。Java 按订单号和用户 ID 联查，旧会话版本失效后拒绝授权。

### P030 Agent 怎么处理缺少订单号或不完整的问题？

先预检订单号、日期和场次等必填槽位，缺失就澄清。补问只使用当前用户本渠道的受限历史，多候选时追问；助手之前猜测的 ID 不能直接作为可信参数。

### P031 AI 会话为什么放 Redis？模型调用失败怎么办？

Redis 保存短期会话、历史、限流和生成锁，长期偏好在 MySQL。GLM 失败可在总预算内回退 Qwen；重排失败保留词法候选。身份核验失败必须拒绝授权，不能沿用旧身份缓存。

### P032 为什么用 SSE？网关是否只是多了一层转发？

SSE 推送执行进度与答复，网关还管理身份、隔离、租约、限流和停止操作。停止会取消下游任务；规划和反思不作为正式聊天内容，收到进度还需等待最终结束事件。

### P033 AI 回答评价如何落库和同步？

网关验证反馈回答属于当前会话，从服务端快照取得原问题与答案，再保存到 Java/MySQL。Dify 反馈尝试同步，同步失败仍保留本地记录；Agent 反馈独立处理。

## 项目·验证与边界

### P034 如何验证并发正确性？

2026-09-26 的测试用真实 MySQL 和执行 Lua 的 Redis，覆盖两百线程抢一座、重复请求、三百线程抢五十座和重复支付，四类各三轮，重复与超卖均为零；它验证一致性，不代表 QPS。

### P035 这个并发测试能说明 QPS 是多少吗？

现有测试直接调用 Service，验证数据一致性，没有完整 HTTP、网络和 MQ 链路，因此没有可信 QPS 结论。吞吐要另做端到端压测，并报告环境、响应分位数和错误率。

### P036 测试中的 RabbitMQ 是真实的吗？

并发一致性测试 mock 了消息发布器，重点验证 Redis、MySQL、事务和状态竞争。真实 RabbitMQ 的延迟、重复消费、重试及死信，需要独立 Broker 集成测试，不能由该报告代替。

### P037 项目目前有哪些明确限制？

支付退款仍模拟，订单消息尚无 Outbox，规则初始召回仍是词法检索。并发报告不证明吞吐，固定题集仍有失败和回归；源码实现也不代表服务器同版部署或生产 SLA。

### P038 如果继续做，你会优先改进什么？

交易侧优先补订单 Outbox、告警和真实中间件端到端测试；AI 侧按失败样本修组合查询与澄清链路，再冻结题集复测。真实支付接入需单独完成供应商沙箱与对账验证。

### P039 你认为这个项目最值得讲的技术难点是什么？

我会讲抢座一致性验证：mock 单测不能证明 Lua 和唯一约束真实生效，所以用真实 Redis、MySQL 做并发竞争，再查库核对重复与超卖。这同时帮助明确正确性测试和吞吐压测的区别。

## 项目·MCP与语义

### P040 为什么“今天排了哪些电影”不能直接查上映中的电影？

上映阶段不代表今天有场次。查询必须保留 scheduled 范围和北京时间当天日期，通过场次关联电影；无排期可以返回空，不能删日期或偷换上映列表，可购买还需 bookable 条件。

### P041 怎样固定北京时间，并区分影片上映时间和场次时间？

每轮固定 Asia/Shanghai 基准日期，当天用左闭右开区间，场次按开场日归属。上映日和场次时间分别约束；起止日期和时段不能丢失，模糊或冲突日期应澄清。

### P042 MCP 与原来的普通 HTTP Tool 相比，具体增加了什么？

MCP 统一初始化、工具发现、JSON Schema、调用结果和错误格式，方便可信客户端复用。项目迁移四类查询，并未改造全部 REST；协议本身不保证业务权限、事务和语义正确。

### P043 工具 Schema 能保证参数安全吗？

Schema 只校验结构和类型，不证明 ID 真实或有权限。编号要来自用户明确输入或本轮核实结果，身份由服务端传递，Java 再查归属；每次 MCP 调用独立身份会话，防止串用户。

### P044 “查场次，再查最早一场空座”如何避免漏查或反复调用？

代码建立查场次、选最早场次和查座位的依赖清单；只能从已核实结果取场次 ID。结果更新任务状态，完成即停，提前结束只补缺项，重复参数被拒绝，预算不足披露未完成部分。

### P045 Java 日志里 `/mcp` 返回 404，该怎样判断？

先确认 404 来自哪个服务：Java 的 8080 返回 /mcp 错误，不等于 MCP 的 8020 宕机。核对 Agent 地址、容器网络及 MCP 健康日志；容器内 localhost 只指自身，不能默认存在 Nginx。

## 项目·记忆与RAG

### P046 用户记忆究竟保存在 Redis、MySQL 还是 Chroma？

Redis 保存短期聊天与控制状态，MySQL 保存长期记忆原文、归属和版本，Chroma 保存 BGE 向量索引。新对话不会清除已确认的长期偏好，MySQL 是事实来源，索引可重建。

### P047 写 MySQL 成功、写 Chroma 失败怎么办？

记忆与索引 Outbox 同一 SQL 事务提交，worker 按租约领取，幂等更新 Chroma，失败重试并检查版本。它实现可恢复的最终一致，不是跨库原子提交；订单消息采用另一套机制。

### P048 向量库还没删完，用户删除的记忆会不会被继续使用？

向量候选必须经 MySQL 复核归属、状态和版本，回答使用 SQL 当前原文。SQL 先失效后，旧向量不能继续参与回答；当前墓碑仍保留原文，不等于所有副本已物理擦除。

### P049 是否所有聊天都会自动变成长期记忆？

普通聊天不会自动保存，用户手动管理或确认“请记住”后才写入，每账号最多两百条、每条五百字。记忆只影响偏好与表达，当前要求优先，订单和票价仍实时查询，Dify 不读取。

### P050 Embedding、向量召回、rerank 在项目里分别做什么？

长期记忆用本地 bge-small-zh-v1.5 生成 512 维向量，Chroma 召回后做 SQL 复核。规则先词法召回，再由 qwen3.7-text-rerank 排序；重排找不回未召回的内容。

### P051 为什么有 rerank 还要保留原始规则？失败怎么办？

Java 当前退票政策独立保留，不能被知识片段覆盖。重排超时、限流或响应异常时回退词法候选并保留来源；默认最多三十候选取四条、五秒超时，不自动重试。

## 项目·执行与评测

### P052 每个问题都要先调用大模型理解吗？

先做确定性槽位预检和 L0 高频规则，未覆盖问题才尝试受限 GLM 路由，失败或复杂任务交给 Qwen。Simple/ReAct 由代码选择；fastText 有扩展代码，不能说已经上线贡献收益。

### P053 GLM 返回 0.95 置信度，就可以直接执行吗？

GLM 自报高置信度不能直接执行，还要校验结构、单任务范围和参数来源。默认阈值 0.90，尝试一次、六秒超时，失败计入预算并回退 Qwen；身份和日期不由分类器编造。

### P054 Simple 与 ReAct 的选择标准是什么？

单对象、单目标且无跨工具依赖走 Simple；先查场次再查座位等组合任务走有界 ReAct。两条路径都经过事实和完成检查，快路径不是免校验，也不能把复杂问题简单化。

### P055 Reflection 是让另一个模型重新回答一次吗？

先以工具事实构建证据块，简单任务做规则验证，其余最多一次结构化反思。反思检查遗漏与无依据断言，不新增工具调用，修订必须保留证据；模型说通过不等于独立评测通过。

### P056 怎样防止 Agent 进入死循环或超出调用成本？

默认业务调用四次、无效或重复三次、ReAct 五步、聊天模型八次、Token 32768、图内六十五秒。调用前预留、返回后核算，超限停止并说明未完成；rerank 成本单独统计。

### P057 提示词改了以后，怎样知道一次实验究竟用了哪个版本？

提示词和规则有版本及内容哈希，按可信用户、会话和实验编号稳定分组，补问保持同组。离线保存源码、配置和业务快照，只比较共同题集，新增题单列，避免变分母制造提升。

### P058 澄清之后用户补充的信息，能直接拿去训练模型吗？

澄清补槽只生成待人工复核的 silver 弱标签。Golden v1 有 168 条、72 个独立场景，用于冻结验收；按 source_case_id 隔离数据集，同场景不同问法不能跨训练测试集泄漏。

### P059 评测里的“成功率”和“准确率”有什么区别？

严格成功要求事实验收、工具名称参数顺序和正常结束同时通过。2026-10-11 的 672 次任务是开发环境单并发固定题集评测，不是线上成功率、HTTP 压测或逐句人工事实审核。

### P060 这版优化能拿出哪些数字？GLM 带来的收益是多少？

2026-10-11 共同题集严格成功由 254/288 到 278/288，即 88.2% 到 96.5%；完整题集为 316/336，约 94.0%。GLM 接管零次，不能把整体提升归因于它，也不能把子集结果当全量。

### P061 rerank 的首位命中率到 100%，是否说明问答准确率到 100%？

2026-10-09 小样本排序专项的首位证据命中从 90% 到 100%，不代表问答准确率。同期 96 次端到端对照未显示严格成功提升；重排也不能修复漏召回或错误业务事实。

### P062 LangSmith 记录了什么？能用 trace 直接计算回答准确率吗？

LangSmith 记录脱敏节点摘要、耗时、结束原因和可用 usage，用 trace_id 关联链路，不上传完整问题、订单或密钥。没有原问题、结果及独立标签，trace 只能定位阶段，不能直接计算事实准确率。

## 项目·账户与报表

### P063 管理员降权后，旧登录为什么会立刻失效？

MySQL 保存 session_version，登录记录保存旧版本；改密码、停用或降权会递增版本，后续授权检查不匹配就拒绝。网关生成中每两秒复核；不会撤回已发内容或回滚已授权事务。

### P064 经营报表怎样保证金额不会重复，也不会算错日期？

支付和退款按各自处理日统计，有效票与上座率按放映日，统一北京时间。支付、退款、票数先分别聚合再合并，避免一对多联表放大金额；跨日退款可使当天净额为负。

### P065 上座率为什么需要场次容量快照？

首次成功锁座事务固定可用座位容量，历史快照不随布局修改。上座率按有效票总数除以容量总数，不平均各场比例；容量缺失显示未知，也不能把无场次伪装成零。

## 项目·运行与讲解

### P066 修改 AI 代码后如何确保启动了新版本？

按 Java、Agent、网关、MCP 边界更新：Java 重建 JAR，前端重新构建，Python、提示词和配置重启对应进程。之后核对版本、服务日志、健康与真实查询，端口有监听不代表新代码生效。

### P067 “内部agent”目录是运行目录还是实时备份？

“内部agent/源文件”是单向同步的最新副本，原后端才是运行源，变更和删除都会同步。它不复制密钥和运行数据，不提供历史恢复；历史靠 Git，复制成功也不代表热更新或部署完成。

### P068 面试时怎样选择最值得展开的新版难点？

后端岗位讲抢座、幂等和补偿；AI 岗位讲查询语义、日期约束、MCP 和任务完成；数据一致性讲记忆 Outbox 与 SQL 复核。每条都说明案例、做法、证据和边界，少堆技术名词。

## 项目·介绍展开

### P069 项目介绍（90秒展开版）

这是一个从排期、选座到出票售后的影院项目，支付退款目前模拟。Java 负责交易，MySQL 保存事实，Redis Lua 原子锁座，行锁和请求号控制并发与幂等，RabbitMQ 延迟取消配合对账释放超时订单。AI 侧由网关核验身份，LangGraph 选择 Simple 或 ReAct，经 MCP 查询真实业务，完成后做规则校验或一次反思。长期记忆采用 MySQL、BGE 和 Chroma，规则知识采用词法召回和可选重排。验证上区分并发一致性、固定题集任务成功与成本，避免把小样本结果说成线上 SLA。

## 八股·Spring

### B001 什么是 IoC 和 DI？

IoC 是把对象创建和依赖管理交给 Spring 容器，DI 是容器通过构造方法等方式注入依赖。这样能降低耦合，也方便替换实现和做测试。

### B002 Spring Boot 和 Spring Framework 有什么关系？

Spring 提供 IoC、AOP、MVC 和事务等核心能力；Spring Boot 在此基础上提供自动配置、Starter 和内嵌服务器，减少配置。数据库地址、密钥等环境参数仍需自行提供。

### B003 一个 HTTP 请求在 Spring MVC 中大致怎样流转？

请求经过 Filter，再由 DispatcherServlet 找到 Controller；Controller 接收参数，Service 执行业务和事务，Mapper 或 JdbcTemplate 访问数据库。结果统一返回，异常由统一异常处理转换为响应。

### B004 Filter、Interceptor 和 AOP 有什么区别？

Filter 在 Servlet 层处理整个请求；Interceptor 在 Spring MVC 层拦截控制器；AOP 拦截 Spring Bean 方法。项目用 Filter 做日志和限流，用事务代理管理数据库事务。

### B005 Spring 的声明式事务是什么？@Transactional 怎么起作用？

Spring 通常通过代理在方法前后开启、提交或回滚事务。默认对 RuntimeException 和 Error 回滚；同类直接调用可能绕过代理。数据库事务不会自动回滚 Redis、HTTP 或 MQ 操作。

### B006 什么是分层？为什么不让 Controller 直接写 SQL？

Controller 管 HTTP 入参和响应，Service 管业务规则与事务，Mapper/Repository 管数据访问。规则集中在服务层，便于复用和测试，也避免权限、状态判断散落在各个接口。

### B007 MyBatis 和 JdbcTemplate 的区别是什么？

MyBatis 通过 Mapper 管理 SQL 和对象映射；JdbcTemplate 是 Spring 对 JDBC 的轻量封装。项目两者都有使用，选择取决于查询复杂度；都应绑定参数，不能拼接用户输入。

### B008 参数校验和统一异常处理为什么重要？

参数校验先拦截格式和范围错误，业务层再检查归属、状态等规则。统一异常处理返回稳定的状态码和错误结构，方便前端区分参数错误、未登录、无权限和业务冲突。

## 八股·MySQL

### B009 ACID 是什么？

ACID 指原子性、一致性、隔离性、持久性，保证数据库事务中的修改满足约束并按配置持久保存。它不自动覆盖 MySQL、Redis、RabbitMQ 之间的跨系统操作。

### B010 数据库事务隔离级别有哪些？

四种隔离级别是读未提交、读已提交、可重复读和串行化，隔离越强通常并发代价越大。项目关键交易还显式加行锁、检查状态和唯一约束，不单靠默认隔离级别。

### B011 什么是索引？为什么常用 B+ 树？

InnoDB 常用 B+ 树，树高低、叶子有序，适合范围查询。聚簇索引叶子保存整行，二级索引保存索引字段和主键，可能需要回表。索引能加速查询，也会增加写入维护成本。

### B012 什么是联合索引的最左前缀原则？

联合索引按列顺序组织，例如（user_id, created_at）通常适合按用户查，或按用户和时间查；只按时间查未必高效。索引应匹配过滤、排序和范围条件，并用 EXPLAIN 验证。

### B013 什么是唯一索引？为什么不能只在 Java 里先查再插？

先查再插存在并发空窗，两个请求可能都查到不存在。唯一约束在数据库写入时仲裁重复；应用负责友好提示，数据库兜底。唯一键仍不能替代全部业务校验。

### B014 行锁、乐观锁和悲观锁有什么区别？

悲观锁先锁行再操作，适合支付、取消等状态竞争；乐观锁通过版本或旧状态条件更新，更新零行说明冲突。行锁范围与索引有关，使用时要缩短事务并统一加锁顺序。

### B015 什么是死锁？项目里怎样降低风险？

死锁是事务互相等待对方持有的锁。项目批量座位按 ID 顺序加锁，并缩短事务、使用合适索引；发生死锁后按幂等规则有限重试，不能无限重试。

### B016 什么是数据库范式？项目为什么要拆订单和订单明细？

范式主要减少冗余和更新异常。订单描述一次购买，明细描述每个座位和票项状态，便于查占座、验票及建立约束。必要冗余可以保留，但要明确事实来源和同步方式。

### B017 金额为什么用 BigDecimal，而不是 double？

double 是二进制浮点数，部分十进制金额无法精确表示。项目用 BigDecimal 和数据库 DECIMAL，并明确精度与舍入；金额由后端根据票价和座位数计算。

### B018 SQL 注入是什么？如何预防？

SQL 注入是用户输入改变 SQL 结构。使用预编译和参数绑定；动态表名、排序字段用白名单。参数校验和最小权限是补充措施，不能替代绑定参数。

## 八股·Redis

### B019 为什么项目同时使用 MySQL 和 Redis？

MySQL 保存订单、支付等持久事实；Redis 保存短期锁、会话、缓存和计数。Redis 锁过期不代表订单失效，最终占座和交易状态仍以 MySQL 为准。

### B020 Redis 常见数据结构有哪些？项目中怎样用？

String 适合锁值、token 和计数；Hash 适合保存会话字段；List、Set、ZSet 分别适合列表、去重和排序集合。Lua 是脚本能力，不是数据结构，项目用它原子校验并修改锁。

### B021 缓存旁路（Cache Aside）是什么？

读时先缓存后数据库，未命中再回填；写时先更新数据库，再删相关缓存。删除失败仍有一致性窗口，需要 TTL、重试或事件补偿；关键交易不能只依赖旧缓存。

### B022 缓存穿透、击穿和雪崩是什么？

穿透是查不存在的数据，可用校验、空值缓存或布隆过滤器；击穿是热 key 过期，可互斥重建；雪崩是大量缓存失效，可分散 TTL、限流降级。这些改进不能都说成项目已实现。

### B023 Redis Lua 怎样保证批量锁座原子性？

Redis 执行 Lua 期间不会穿插其他命令。锁座脚本先检查所有键，发现冲突就返回；全部可用才批量写锁，避免正常冲突时只锁一部分。它不包含 MySQL 的事务。

### B024 座位锁为什么要有 TTL 和持有人校验？

TTL 防止用户离开后长期占座。解锁时用 Lua 原子比较持有人再删除，避免旧请求误删后来者的新锁。临时锁失效后，最终占座仍需检查数据库有效订单。

### B025 项目的座位锁算不算分布式锁？

项目的 Redis 锁更准确地说是短期座位租约，可能受过期、网络或故障影响。最终交易还靠 MySQL 行锁、状态和约束保护；高风险写入可进一步设计 fencing token。

### B026 限流如何实现？固定窗口有什么问题？

项目用 Redis Lua 原子计数实现分钟固定窗口限流，默认每分钟 120 次。窗口边界可能出现双倍突发，更平滑可选滑动窗口或令牌桶；Redis 异常时当前限流选择放行。

## 八股·RabbitMQ

### B027 为什么用消息队列取消超时订单？

超时取消不能依赖前端倒计时，也不应让下单请求等待五分钟。项目提交订单后发延迟消息，到期通知消费者检查数据库状态，再取消仍未支付的订单。

### B028 Exchange、Queue 和 Routing Key 是什么？

Exchange 接收并路由消息，Queue 保存待消费消息，Routing Key 决定路由匹配，Binding 定义交换机与队列的关系。项目使用 Direct Exchange 按明确路由键发送取消消息。

### B029 什么是死信队列和延迟队列？

项目用队列 TTL 加死信路由实现延迟通知，没有依赖延迟插件。到期消息进入取消队列，重试耗尽进入失败队列；消息到期只是提醒，是否取消仍查订单状态和到期时间。

### B030 什么是 ACK？为什么使用手动确认？

ACK 表示消息已处理。手动 ACK 能在业务处理完成后确认，减少确认后崩溃造成的遗漏。项目成功或重复消费后确认，失败有限重试，耗尽后进入失败队列。

### B031 消息队列能保证消息只消费一次吗？

消息可能因断网或重启重复投递，因此消费端必须幂等。项目用稳定 messageId 和唯一消费记录防重，记录与取消业务同事务；失败一起回滚，重试仍可处理。

### B032 订单入库和消息发送怎样避免不一致？

数据库提交后再发消息仍可能出现提交成功、消息丢失。Outbox 将业务数据和待发事件同事务保存，再由后台重试投递；消费端仍要幂等。项目订单消息目前用提交后发布加对账补偿。

### B033 为什么还要定时对账任务？

定时对账直接扫描 MySQL 过期未支付订单，补偿消息发布或消费失败。行锁和状态条件保护重复处理；当前多实例仍可能重复扫描，后续可用任务领取或分片减少重复工作。

## 八股·并发与幂等

### B034 什么是幂等？为什么创建订单需要幂等？

幂等是同一业务请求重试多次，只产生一个有效结果。项目用用户 ID 加 requestId 和唯一约束防重复下单，支付用 paymentNo；超时重试必须复用原幂等键。

### B035 什么是竞态条件？选座为什么会有竞态？

竞态是并发结果依赖执行交错。两个请求都查到座位空闲再写订单就可能冲突。项目用 Redis 原子锁座、MySQL 行锁、有效订单复核和唯一约束组合保护。

### B036 什么是状态机？为什么订单状态不应随便改？

状态机明确允许的状态转换，例如未支付可支付或取消，已出票才可按规则退款。更新前锁行校验，SQL 带旧状态条件并检查影响行数，避免并发做出矛盾转换。

### B037 Redis 锁、数据库行锁和唯一约束各自解决什么？

Redis 锁减少选座阶段竞争，数据库行锁串行处理持久状态，唯一约束拒绝重复事实。三者解决不同问题；同一订单内座位唯一键，不能单独防止跨订单重复占座。

### B038 CAP 是什么？本项目要怎么回答？

CAP 讨论网络分区时一致性与可用性的取舍。项目关键交易无法确认状态时不能直接成功，非关键功能可降级。MySQL、Redis 和 MQ 之间仍需幂等和补偿，不宣称全局强一致。

## 八股·HTTP与鉴权

### B039 401 和 403 的区别？

401 是缺少有效身份，403 是身份有效但权限不足。登录成功也不能查询他人订单，后端必须把订单号与可信用户 ID 一起校验。

### B040 BCrypt 是什么？为什么不直接保存密码或做可逆加密？

BCrypt 是带随机盐的慢哈希，登录时比对哈希，不还原密码。它提高离线暴力尝试成本；项目不保存明文，也不向管理接口返回密码哈希。

### B041 项目使用的是 JWT 吗？

项目没有使用 JWT，而是随机 opaque token，Redis 保存身份和会话，TTL 为两小时。撤销和降权还检查数据库会话版本，旧 token 即使未过期也会失效。

### B042 X-Internal-Token 能否替代用户鉴权？

内部 token 只能证明服务身份，不能证明用户身份或订单归属。用户身份由网关核验并在服务端传递，Java 再限制本人订单；内部密钥不能交给浏览器或模型。

### B043 为什么信任 X-Real-IP 需要谨慎？

客户端可伪造 X-Real-IP，应用只能在请求来自可信代理时采信。代理应覆盖相关头，不能直接透传用户输入；项目当前环境是否有代理要按实际部署确认。

### B044 REST API 常见方法和状态码怎么理解？

GET 读取，POST 创建或触发动作，PUT 整体替换，PATCH 部分修改，DELETE 删除。常用状态码有 200/201 成功、400 参数错误、404 不存在、409 冲突、429 限流和 500 服务异常。

## 八股·AI与流式

### B045 什么是大语言模型？模型回答为什么会编造？

大模型根据上下文预测文字，语言流畅不代表事实正确。实时票价和订单要查后端，静态规则要检索资料，再约束回答以已核实结果为依据。

### B046 什么是 RAG？项目中的 RAG 用了向量数据库吗？

RAG 是先检索资料，再交给模型组织回答。新版项目规则知识使用关键词召回和可选 rerank；BGE 与 Chroma 用于长期记忆，不能把两条检索链混为一谈。

### B047 什么是 Agent？Agent 和普通聊天有什么不同？

普通聊天主要直接生成文字，Agent 能按任务选择受控工具，获取外部事实后回答。项目显式编排理解、澄清、查询和验证，但不赋予模型任意 SQL 或交易写权限。

### B048 LangGraph 在项目里解决什么问题？

LangGraph 用状态图组织多步任务，节点负责阶段，边决定流转。它方便加入澄清、工具循环、失败处理和验证，比完全依赖一段提示词更可控，也更容易测试。

### B049 如何降低 AI 幻觉和越权风险？

实时事实走受控工具，身份和归属由后端校验；Schema 之外还检查参数来源和任务完整性。交易写操作回到正式页面，历史聊天不作为授权或订单事实。

### B050 SSE 是什么？为什么这里用 SSE 而不是 WebSocket？

SSE 用一个 HTTP 响应持续推送文本，适合提问后单向输出 AI 回答；WebSocket 更适合持续双向通信。SSE 仍需处理取消、超时和分包；有代理时需检查缓冲配置。

### B051 AI 网关为什么单独存在？

AI 网关负责身份校验、Dify/Agent 分流、会话隔离、限流、生成控制和 SSE 转换。拆分便于独立迭代，但增加内部调用和运维成本，需要清晰边界。

## 八股·前端联调

### B052 TypeScript 能保证请求数据正确吗？

TypeScript 只提供编译期检查，不会自动校验收到的 JSON。接口数据仍需运行时验证，后端还要做参数、权限和数据库约束检查。

### B053 为什么前端不应决定票价、权限和订单状态？

浏览器可被用户修改，金额、角色和状态不能由前端决定。后端重新计算票价、验证身份和状态；前端禁用按钮只改善体验，不能替代幂等与权限控制。

### B054 接口请求超时后，前端该怎么办？

超时只表示客户端没及时收到响应，不代表服务端失败。下单和支付应查询结果，或复用原 requestId、paymentNo 有限重试，避免生成新标识导致重复操作。

## 八股·Java基础

### B055 HashMap 是怎样查找数据的？线程安全吗？

HashMap 根据哈希定位桶，冲突使用链表，满足条件时树化；它不保证线程安全。并发场景可用 ConcurrentHashMap，但先读再写等复合操作仍需原子 API 或额外协调。

### B056 equals 和 hashCode 为什么要一起实现？

equals 为 true 的对象必须有相同 hashCode，反之不一定。只重写 equals 可能导致哈希集合查找失败；作为 key 的关键字段也不应在放入 Map 后修改。

### B057 volatile、synchronized 和原子类有什么区别？

volatile 保证可见性并限制重排，不保证 i++ 原子；synchronized 提供互斥与可见性；原子类适合简单原子更新。进程内锁不能自动保护跨服务器的订单竞争。

### B058 线程池有哪些核心参数？为什么不建议无限制创建线程？

核心参数包括核心/最大线程数、任务队列、存活时间和拒绝策略。线程或队列无界会耗尽资源，应按 CPU/IO 特征配置并监控。项目没有单独为订单声明自定义线程池。

### B059 JVM 堆、栈和垃圾回收怎么解释？

线程栈保存调用与局部变量，堆主要保存共享对象，GC 回收不可达对象。GC 不保证内存永远够用；排查应结合堆趋势、GC 日志、线程和请求，不能只加内存。
