# 0.1.1 连续提问与通用八股回答修复

日期：2026-10-14。

## 用户报告

面试官转录持续更新，但 AI 有时以没有相关知识库为由不回答；首题可回答，后续几题长时间没有反应。

## 已修复

- 通用技术题明确使用模型自身知识，本地题库作为可选参考；个人经历、已实现功能和真实指标仍以提供的事实为准。低相关词法候选不再强行放入模型背景。
- 语音活动帧不再不断重置提问计时器。正常停顿仍用于分句；背景声音持续存在时，最终文本稳定 1 秒或中间文本稳定 1.6 秒也可触发生成。文本持续变化时继续跟踪，不按固定总时长截断提问。
- 支持 HashMap、JVM、Redis 缓存等省略问号的技术题。短间隔内的独立问题分别生成；不再把所有连续提问都当作上一题修订。旧句最终修订不会覆盖已收到的新问题草稿。
- 本地检索失败或等待超过 1.2 秒时仍调用已配置模型。首字等待上限 10 秒、输出中断上限 8 秒、整次生成上限 30 秒；失败显示原因，后续新问题可正常请求。输出上限调整为 500 tokens，回答提示要求精炼口述。
- AI 栏显示实时提问草稿和检索/模型请求阶段。新增“回答最新问题”，可立即提交草稿或重试最近的问题；同一问题修订替换原卡片，迟到旧回答不能覆盖新回答。
- 会话进行中保存 DeepSeek 模型、密钥和个人背景，下一题即可使用；语音采集配置仍需重新开始会话。
- 诊断记录增加提问触发、生成阶段和错误原因，保留不记录密钥、简历与原始音频的约束。

## 验证

- 类型检查通过；4 个测试文件共 30 项检查通过。
- Windows 安装包构建成功；打包后隐藏启动退出码 0，页面、预加载接口、SQLite worker 和 FTS5 检查通过，格式检查通过。
- 新增回归覆盖：持续回环噪声下连续 8 题、稳定中间结果、迟到修订保留后题、即时提交/重试、空题库模型回答、连续 8 次生成、检索失败/卡住、首字超时后恢复、新问题取消旧请求、无 DONE 但明确 stop 的完整流、前端进度及修订。
- 使用本机已保存的 DeepSeek 配置，关闭本地题库和简历注入，连续调用 HashMap、Redis 缓存和 Spring 事务三题，全部完成且未因缺少知识库拒答。本次首字为 480—670 毫秒，完整回答为 1448—1572 毫秒；这是本次联调观测，不是延迟保证。仅记录状态、字数和耗时，未保存密钥或模型回答正文。
